# 记者选拔回避与复核

本仓库把第十三届活动的选拔过程建设成可复核的运行系统：二百三十名记者分六组复赛，四十五人进入训练营和决赛。推荐资格、组别、稿件附件版本、抽签场次、关系声明、回避替补、评分维度、现场事实、技术中断、申诉、训练营反馈和最终决定全部以相互关联的领域事件记录，秘书处可从最终名单反查全过程。

## 结构

- `contracts/domain.schema.json`：事件信封与全部事件类型、聚合类型的契约。
- `src/events.js`：事件目录与各事件的载荷约束（如更正必须附理由）。
- `src/store.js`：追加式事件存储；事件写入即冻结，版本按聚合严格递增，不提供修改或删除。
- `src/rules.js`：第十三届冻结规则（六组名额合计 45、最低有效评委数、并列比较维度、申诉期、稿件截止时刻）。
- `src/service.js`：写入侧。所有命令校验角色与不变量后追加事件。
- `src/projections.js`：只读投影——有效评分链、组内榜、留存状态、反查追踪、晋级影响解释。
- `src/views.js`：角色视图——参赛者、评委、秘书处各自只能读到履行职责所必需的内容。
- `tests/`：契约测试与场景测试（临场换稿、同单位回避、设备故障、更正链、弃权缺席、名额并列、申诉留存、最终反查、视图权限）。

## 关键不变量

- 规则经 `RULES_FROZEN` 冻结后，名额、并列与最低有效评委数的计算只引用冻结快照；冻结后修改外部对象不影响结果。
- 截止后提交的稿件版本属临场更换，须资格审核人员确认才作评分材料；被驳回则沿用上一已确认版。上场记录锁定所用稿件版本，十佳名单采用的是哪轮证据由此还原。
- 同单位、师生、合作关系由系统扫描提示，有权限人员确认后才登记回避并安排替补；提示未处理时该评委不能评分。替补评委的视图中不含任何他人已交分数。
- 已提交的评分只能通过附理由的 `SCORE_CORRECTED` 后继事件修订，原记录保留成链，榜单取最新值。
- 弃权、缺席是评分单的独立终态，与技术中断的上场记录互不混淆；有效评分低于冻结规则的最低评委数时不排名、标记待复核。
- 名额边界仍并列时按冻结策略同时晋级。
- 申诉期内或有未结申诉时，当轮稿件与现场记录必须保留（`retentionStatus` 可检查）。
- 最终决定事件引用当轮证据：稿件版本、上场记录、评分与更正链事件编号、申诉编号、规则届次。

## 角色

`secretariat`（秘书处，全量与最终决定）、`eligibility_officer`（资格与稿件版本）、`conflict_confirmer`（回避确认）、`judge`（仅所分配场次）、`camp_mentor`（训练营反馈）、`system`（冲突自动提示）。参赛者通过 `participantView` 查看本人材料与可公开理由，申诉由秘书处登记。
